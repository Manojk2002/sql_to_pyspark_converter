🔄 SQL RDBMS Cursor vs PySpark

              

                SQL cursors iterate row-by-row on the database server.
                PySpark processes data in bulk across a distributed cluster.
                They are fundamentally different — direct translation causes performance disasters.
              

            


            
            

              ⚠ NEVER use .collect() + Python loop in PySpark

              This loads all rows into driver memory — identical to the cursor anti-pattern.
              On a 1 billion row table it will crash the driver node.
            


            
            
📄 Conversion Mapping

            

            

              
                

                  SQL RDBMS (Cursor)
                  Intent
                  PySpark Equivalent
                

              
              
                

                  DECLARE cur CURSOR FOR SELECT ...
                  Define source rows
                  source_df = spark.sql("SELECT ...")
                

                

                  OPEN cur
                  Open cursor
                  # no-op in Spark (lazy evaluation)
                

                

                  FETCH NEXT INTO @vars
                  Get one row
                  # eliminated — Spark is set-based
                

                

                  UPDATE t SET col=@v WHERE id=@id
                  Update per row
                  spark.sql("UPDATE db.t SET col=val WHERE ...")
# requires Delta Lake		
                

                

                  INSERT INTO t VALUES (@a, @b)
                  Insert per row
                  spark.sql("INSERT INTO db.t SELECT a, b FROM source")
                

                

                  DELETE FROM t WHERE id=@id
                  Delete per row
                  spark.sql("DELETE FROM db.t WHERE cond")
# requires Delta Lake		
                

                

                  SET @col = func(@val)
                  Transform per row
                  df = df.withColumn("col", expr("func(val)"))
                

                

                  WHILE @@FETCH_STATUS = 0 ...
                  Loop
                  df.foreachPartition(func) ⚠ last resort
                

                

                  CLOSE / DEALLOCATE cur
                  Release cursor
                  # no-op — Spark GC handles cleanup
                

              
            

            


            
            
📄 Side-by-Side Code Example

            

              

                
❌ SQL RDBMS Cursor (do NOT port directly)

                
DECLARE @id INT, @sal DECIMAL
DECLARE emp_cur CURSOR FOR
  SELECT emp_id, salary
  FROM Employees
  WHERE dept_id = 10

OPEN emp_cur
FETCH NEXT FROM emp_cur
  INTO @id, @sal

WHILE @@FETCH_STATUS = 0
BEGIN
  UPDATE Employees
  SET salary = @sal * 1.1
  WHERE emp_id = @id

  FETCH NEXT FROM emp_cur
    INTO @id, @sal
END

CLOSE emp_cur
DEALLOCATE emp_cur

              

              

                
✅ PySpark Equivalent (bulk, distributed)

                
from pyspark.sql import SparkSession

def raise_salaries(
    spark: SparkSession,
    dept_id: int = 10
):
    """
    Raise salary by 10% for all employees
    in the given department.
    Replaces row-by-row cursor with one
    bulk Delta Lake UPDATE.
    """
    # NOTE: SQL cursor replaced with
    # single bulk UPDATE (set-based)
    spark.sql(f"""
        UPDATE my_db.Employees
        SET salary = salary * 1.1
        WHERE dept_id = {dept_id}
    """)

    result_df = spark.sql(f"""
        SELECT emp_id, salary
        FROM my_db.Employees
        WHERE dept_id = {dept_id}
    """)
    print("Updated rows:", result_df.count())
    result_df.show(10, truncate=False)
    return result_df

              

            


            
            

              🚀 Performance impact:
              A cursor processing 1M rows takes hours in SQL Server.
              The PySpark bulk UPDATE on a Delta table with Databricks runs in
              seconds — parallelised across all worker nodes.
